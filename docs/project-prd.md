# Stock-Claw 项目级 PRD

## 1. 文档信息

- 项目名称：`Stock-Claw`
- 文档类型：项目级 PRD
- 当前阶段：`从原型演进到可落地产品`
- 文档目标：明确产品目标、用户价值、V0 快速可跑方案、项目级功能范围、迭代优先级与阶段路线

## 2. 背景与机会

当前项目已经具备基础原型能力：

- 实时行情查看
- 个股详情查看
- 资金流与市场快讯
- LLM 驱动的基础选股分析
- 本地 SQLite 数据存储

但从产品角度看，当前系统更接近一个“可演示原型”，尚未形成真正具有持续使用价值的投研工作流。

市场上大部分股票工具存在三个共性问题：

- 只能提供行情，不理解用户关注的“人”和“观点”
- 能做问答，但无法绑定盘中真实走势
- 信息很多，但难以形成个人可追踪、可复用的研究闭环

`Stock-Claw` 的机会在于将以下几类能力融合到一个统一工作台中：

- 实时市场数据
- 高价值论坛人物观点监听
- 人物投资风格蒸馏
- 观点与盘中行情的动态联动
- 基于证据的 Agent 分析与指导

## 3. 产品愿景

打造一套面向高频市场观察与研究决策的智能投研工作台，使用户能够：

- 实时跟踪行情与资金变化
- 自动监听高价值论坛指定人物的新观点
- 将不同人物长期发言沉淀为可调用的投资风格 skill
- 将最新观点自动映射到真实盘中走势与关键市场信号
- 在一个统一界面中完成发现、分析、跟踪、记录与复盘

## 4. 产品定位

`Stock-Claw` 是一个面向个人研究型投资者与盘中高频观察用户的：

`论坛情报 + 人物认知 + 盘中联动 + 行情工作台 + Agent 分析平台`

它不是简单的聊天机器人，也不是普通行情软件，而是一个能把“谁说了什么”和“市场现在怎么走”实时结合起来的研究系统。

## 5. 目标用户

### 5.1 核心用户

- 高频盯盘用户
- 依赖论坛、社群、题材轮动做判断的交易型用户
- 希望沉淀自己研究体系的个人投资者
- 需要从多位“市场人物”中提取方法论并辅助判断的用户

### 5.2 典型用户画像

#### 用户 A：题材交易者

核心需求：

- 盯住关键论坛人物和题材风向
- 快速判断盘中回流、分歧、转强
- 获取简洁直接的盘中辅助建议

#### 用户 B：研究整理型用户

核心需求：

- 长期沉淀某些人物的投资风格
- 把发言变成可追踪的知识资产
- 对不同人物观点做对照分析

#### 用户 C：工具驱动型用户

核心需求：

- 一站式查看行情、快讯、观察池、分析结果
- 减少来回切换论坛、行情软件、笔记工具的成本

## 6. 核心问题定义

当前需要解决的关键问题包括：

### 6.1 信息捕获问题

高价值观点往往散落在论坛帖子中，需要人工刷新和筛选，效率低且容易漏掉关键发言。

### 6.2 信息理解问题

即使抓到了发言，用户仍然需要自己判断：

- 提到了什么对象
- 在说什么方向
- 是短线观点还是中线判断
- 观点是否发生变化

### 6.3 信息落地问题

很多发言提到的是：

- 大盘黄线
- 板块回流
- 龙头强弱
- 个股弱转强

这些说法如果不自动绑定到真实行情，就很难形成实时有效的辅助工具。

### 6.4 研究沉淀问题

不同人物的长期风格、偏好、方法论和信号体系很难被系统化整理，导致高价值认知资产无法复用。

### 6.5 盘中行动问题

用户不是只想“知道”，更想知道：

- 现在市场是否符合某人物的判断
- 哪些条件已经触发
- 当前该观察、等待、跟随还是回避

## 7. 产品目标

### 7.1 短期目标

先快速迭代出一个最基础但能跑起来的版本，验证以下核心链路：

- 监听一个 NGA 帖子
- 抽取指定人物新发言
- 实时推送
- 简单日报
- 对发言中的股票/板块/大盘对象做初步识别
- 结合实时行情给出基础盘中解释

### 7.2 中期目标

形成完整的产品工作台：

- 行情工作台
- 论坛监听面板
- 人物中心
- 盘中观点联动面板
- Agent 研究助手

### 7.3 长期目标

形成一个具有持续进化能力的投研平台：

- 多帖子、多作者、多论坛支持
- 多人物对照分析
- 更强的人物 skill 与市场 skill 编排
- 完整的研究记录与复盘能力

## 8. 非目标

为控制范围，以下内容不作为 V0 的目标：

- 自动交易
- 券商下单接入
- 多角色企业级权限管理
- 覆盖所有股票论坛与资讯源
- 高复杂度回测系统
- 自研大模型训练

## 9. 产品策略

### 9.1 总体策略

采用“两段式推进”：

#### 第一段：快速可跑版

先脱离复杂架构，用简易脚手架和轻量逻辑把最核心闭环跑通，优先验证产品价值，而不是追求系统优雅。

#### 第二段：项目级正式演进

在 V0 闭环验证后，再按项目级功能顺序逐步演进到统一架构，补齐调度、存储、技能编排、工作台与研究闭环。

### 9.2 为什么先做快速可跑版

- 尽快验证用户是否真的会高频使用
- 尽快验证论坛监听与人物联动是否有价值
- 避免前期被完整架构和过多抽象拖慢节奏
- 先用最短闭环把“产品灵魂”跑起来

## 10. V0 快速可跑版定义

### 10.1 V0 产品目标

做出一个“最小但可用”的工具，至少满足：

- 能监听一个 NGA 帖子
- 能过滤指定作者
- 能抓到新发言并去重
- 能在页面查看新发言
- 能推送到一个外部渠道
- 能做一个简版按日汇总
- 能识别发言中提到的股票、板块或大盘黄线等对象
- 能拉取对应实时行情并给出基础盘中提示

### 10.2 V0 产品形态

V0 不强求完整统一工作台，可以接受：

- 一个简单前端页面
- 一个轻量 Node 服务
- 一个本地 SQLite 数据库
- 一套最小抓取脚本与定时轮询逻辑

### 10.3 V0 推荐实现方式

优先选择：

- 沿用当前 `React + Fastify + SQLite`
- 用简化目录快速搭起 `forum / persona / intraday` 三块最小模块
- 可接受临时脚手架式实现，但必须保证后续容易迁移

### 10.4 V0 必须包含的功能

#### 功能 1：帖子监听

- 支持配置一个 NGA 帖子 URL
- 支持配置一组关注作者
- 支持轮询抓取新消息
- 支持增量去重

#### 功能 2：实时消息流

- 页面展示最近抓到的新发言
- 展示作者、时间、正文、提及对象
- 标注是否已推送

#### 功能 3：即时推送

- 支持一个推送渠道
- 对命中的新发言发送提醒

#### 功能 4：日报

- 每天固定时间生成简版汇总
- 至少包括：按人汇总、按股票汇总、按主题汇总

#### 功能 5：基础观点识别

- 识别股票代码、股票名称
- 识别板块名称
- 识别大盘黄线、白线、回流、弱转强等高频术语

#### 功能 6：基础盘中联动

- 发言提到个股时，展示实时价格、涨跌幅、分时简述
- 发言提到板块时，展示板块走势与核心股
- 发言提到黄线时，展示市场风格与黄白线强弱解释

#### 功能 7：基础 Agent 问答

- 支持询问某人物今天说了什么
- 支持询问某人物提到的票现在表现如何
- 支持询问某观点当前是否成立

## 11. V0 用户流程

### 11.1 帖子监听流程

1. 用户配置帖子 URL 与作者名单
2. 系统开始定时抓取
3. 新发言进入消息流
4. 命中规则则立即推送
5. 发言被存档用于后续蒸馏和分析

### 11.2 盘中联动流程

1. 系统识别一条发言中的市场对象
2. 将对象绑定到真实行情实体
3. 页面显示当前行情状态
4. 系统输出基础提示，例如：
   - 当前板块未回流
   - 当前黄线仍弱
   - 个股尚未出现确认信号

### 11.3 日报流程

1. 到达设定时间
2. 系统汇总当日新发言
3. 按人、按票、按主题聚合
4. 生成摘要并投递

## 12. V0 成功标准

### 12.1 功能成功标准

- 能稳定监听一个帖子至少 1 个交易日
- 能正确识别指定作者的新发言
- 推送重复率低
- 日报能稳定生成
- 对股票、板块、黄线等对象有基础识别能力
- 用户能从系统中看到“观点与行情已绑定”

### 12.2 产品成功标准

- 用户愿意在盘中持续打开工具查看
- 用户愿意依赖推送而非手动刷帖子
- 用户认为“人物观点 + 实时行情”的组合有明显价值

## 15. 核心功能需求详述

### 15.1 帖子与作者管理

#### 用户价值

让用户能够明确指定自己要监控的帖子与人物，而不是被动接收全量信息。

#### 需求点

- 添加/编辑/删除帖子配置
- 添加/编辑/删除作者配置
- 配置抓取间隔
- 查看当前运行状态

### 15.2 发言抓取与去重

#### 用户价值

确保用户看到的是稳定、连续、不重复的新发言流。

#### 需求点

- 增量抓取
- 内容去重
- 楼层识别
- 编辑识别
- 抓取失败重试

### 15.3 发言结构化理解

#### 用户价值

让系统能理解“人在说什么”，而不是只保存原文。

#### 需求点

- 提及股票识别
- 提及板块识别
- 提及指数与黄白线识别
- 高频术语识别
- 方向与情绪初步判断

### 15.4 实时推送

#### 用户价值

盘中不必持续盯帖子，也不会漏掉关键人物新观点。

#### 需求点

- 新发言即时提醒
- 支持至少一个外部渠道
- 去重和限频
- 查看推送历史

### 15.5 日报系统

#### 用户价值

将零散信息整理成每日研究摘要，便于复盘与沉淀。

#### 需求点

- 按人汇总
- 按股票汇总
- 按主题汇总
- 观点变化摘要

### 15.6 人物画像与 Skill

#### 用户价值

让不同人物的长期方法论和风格变成系统可调用的研究资产。

#### 需求点

- 人物画像生成
- 代表发言抽取
- 常见信号总结
- 风险偏好标注
- 人物视角分析能力

### 15.7 盘中观点联动

#### 用户价值

把一句论坛发言真正接到盘中行情，形成实时辅助判断。

#### 需求点

- 将自然语言对象绑定到真实行情
- 生成盘中观察任务
- 给出当前状态解释
- 输出基础建议
- 标注失效条件

### 15.8 Agent 研究助手

#### 用户价值

让用户能通过自然语言快速调用市场数据、论坛情报、人物 skill 和盘中状态。

#### 需求点

- 问某人今天说了什么
- 问某个票被谁提到过
- 问某观点现在是否成立
- 问不同人物怎么看同一个对象

## 17. 数据与内容策略

### 17.1 数据来源优先级

第一优先级：

- NGA 指定帖子
- 股票实时行情
- K 线与分时

第二优先级：

- 板块行情
- 资金流
- 新闻快讯

第三优先级：

- 其他论坛
- 公告与财务
- 更复杂的市场情绪数据

### 17.2 人物数据策略

- 先聚焦少量高价值作者
- 先以样本密度高的人物为主
- 先做“可解释蒸馏”，不急于做复杂训练

## 19. 风险与对策

### 19.1 抓取稳定性风险

风险：

- NGA 页面结构变化
- 登录态问题
- 限流或反爬

对策：

- 封装独立连接器
- 保留原始快照
- 做失败重试与告警

### 19.2 观点识别风险

风险：

- 黑话多
- 隐喻多
- 反讽和半句表达多

对策：

- 规则优先
- 支持人工纠错
- 后续再引入更强模型与词典

### 19.3 盘中建议误导风险

风险：

- 用户误将系统建议视为确定性结论

对策：

- 明确标注证据来源
- 区分“观察建议”和“确认建议”
- 输出失效条件与风险提醒

### 19.4 范围失控风险

风险：

- 过早进入复杂架构、复杂页面、复杂数据源

对策：

- 严格先做 V0 最小闭环
- V0 只支持一个帖子、一组作者、一个推送渠道

- 用户能沉淀人物风格与研究记录

## 24. PRD 结论

本项目不应直接从复杂完整架构起步，而应先用简易脚手架快速产出一个最基础、最核心、最能体现差异化价值的版本。

这个最小版本的本质不是“做一个新页面”，而是跑通以下产品闭环：

`指定人物发言监听 -> 新消息捕获 -> 结构化理解 -> 行情联动 -> 推送/日报 -> 基础 Agent 查询`

在这个闭环被验证有效之后，再按项目级功能顺序逐步建设：

- `Forum Intel`
- `Persona Engine`
- `Intraday Insight Engine`
- `Stock Workbench`
- `Agent Runtime`

这将是 `Stock-Claw` 从原型项目演进为完整投研平台的产品路线。
