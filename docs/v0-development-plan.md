# Stock-Claw V0 开发任务拆解

## 1. 文档目标

本文档将 `V0 实施蓝图` 进一步拆解为可直接执行的开发计划。

目标不是描述最终架构，而是明确：

- 先做什么
- 后做什么
- 每一步的交付物是什么
- 每一步的完成标准是什么
- 哪些工作可以暂时简化

## 2. V0 总体开发策略

V0 的开发采用 `单闭环、短周期、边做边验证` 的推进方式。

执行原则如下：

- 每个阶段都必须产生可运行结果
- 每个阶段都必须可在页面或接口层验证
- 每个阶段都优先复用当前项目已有能力
- 先打通链路，再补体验和抽象

## 3. V0 总任务拆分

V0 开发拆为 8 个任务包：

1. `V0 基础骨架`
2. `帖子抓取与解析`
3. `消息入库与去重`
4. `前端消息流`
5. `提及识别与行情绑定`
6. `推送与日报`
7. `简版 Agent`
8. `联调与验收`

## 4. 任务包 1：V0 基础骨架

### 目标

在当前项目中建立 V0 所需的最小目录、类型、配置和基础表结构。

### 交付物

- 后端 `server/src/v0/` 目录骨架
- 前端 `client/src/features/v0/` 目录骨架
- V0 SQLite 表初始化逻辑
- V0 基础配置接口

### 具体任务

- 创建后端目录：
  - `server/src/v0/forum`
  - `server/src/v0/market`
  - `server/src/v0/digest`
  - `server/src/v0/push`
  - `server/src/v0/agent`
  - `server/src/v0/shared`
- 创建前端目录：
  - `client/src/features/v0/pages`
  - `client/src/features/v0/components`
- 增加 V0 共享类型文件
- 增加 V0 表初始化逻辑
- 增加配置读写接口

### 完成标准

- 服务启动后自动初始化 V0 表
- 可通过接口读取和保存帖子 URL、作者名单、抓取间隔

### 验证方式

- 调用 `GET /api/v0/config`
- 调用 `POST /api/v0/config`
- 检查 SQLite 中表是否创建成功

## 5. 任务包 2：帖子抓取与解析

### 目标

实现从指定 NGA 帖子抓取原始内容并解析出结构化消息。

### 交付物

- `ngaConnector`
- `messageParser`
- 手动抓取接口

### 具体任务

- 实现帖子 HTML 拉取
- 实现消息结构提取：
  - 楼层
  - 作者
  - 时间
  - 正文
  - 原始来源链接
- 增加手动触发抓取接口

### 完成标准

- 能成功解析出白名单作者的发言列表
- 至少支持一个目标帖子稳定解析

### 验证方式

- 调用 `POST /api/v0/poll`
- 查看抓取结果是否落到临时日志或响应中

### 暂时简化

- 先不处理复杂楼中楼
- 先不处理帖子分页深翻
- 先聚焦最新页或最新增量

## 6. 任务包 3：消息入库与去重

### 目标

将抓到的消息稳定入库，并避免重复消息反复进入系统。

### 交付物

- `messageStore`
- `thread cursor` 读写逻辑
- 去重策略

### 具体任务

- 基于 `floor_id + author_name + content_hash` 做去重
- 保存最新游标
- 将消息落入 `v0_forum_messages`
- 标记哪些消息是新增消息

### 完成标准

- 同一次抓取不会重复入库
- 多次轮询时只新增真正新消息

### 验证方式

- 连续调用 2 到 3 次抓取接口
- 检查数据库记录数是否合理递增

## 7. 任务包 4：前端消息流

### 目标

让用户能够直接看到系统抓到的新发言和当前抓取状态。

### 交付物

- `V0MonitorPage`
- `V0MessagesPage`
- 基础导航入口
- 消息流组件

### 具体任务

- 增加 V0 页面路由
- 配置页展示：
  - 帖子 URL
  - 作者白名单
  - 抓取间隔
  - 手动抓取按钮
- 消息流页展示：
  - 作者
  - 时间
  - 原文
  - 是否已推送

### 完成标准

- 用户无需查数据库即可看到最新消息
- 能手动触发一次抓取并在页面看见结果

### 验证方式

- 启动前端后访问 V0 页面
- 执行一次抓取
- 页面出现最新消息

## 8. 任务包 5：提及识别与行情绑定

### 目标

让系统开始理解发言内容，并把提到的对象连接到真实市场行情。

### 交付物

- `messageEnricher`
- `marketBinding`
- `marketSummary`
- 前端联动卡片

### 具体任务

- 识别三类对象：
  - 个股
  - 板块
  - 黄线/白线
- 对识别出的对象调用已有行情接口
- 生成两类文本：
  - `summary_text`
  - `advice_text`
- 在消息流中展示联动结果

### 完成标准

- 至少能正确处理以下场景：
  - 发言提到个股
  - 发言提到板块
  - 发言提到黄线

### 验证方式

- 手工构造或等待真实发言
- 检查联动结果是否显示在页面中

### 暂时简化

- V0 不做复杂假设树
- V0 不做持续观察任务
- 一条消息只生成一次简版联动结果

## 9. 任务包 6：推送与日报

### 目标

让系统从“页面可看”变成“可主动通知、可做复盘”。

### 交付物

- `pushService`
- `digestService`
- 推送记录表
- 日报记录表

### 具体任务

- 接入一个推送渠道
- 对新增消息发送即时提醒
- 记录推送状态
- 增加日报生成逻辑
- 提供日报查看接口

### 完成标准

- 新发言可以自动推送
- 可以生成当天日报并保存

### 验证方式

- 新增一条命中消息
- 检查是否成功发送推送
- 调用日报接口查看汇总结果

### 暂时简化

- 日报先使用固定模板
- 推送失败只做记录，不做复杂告警链路

## 10. 任务包 7：简版 Agent

### 目标

给 V0 提供一个能真正使用的自然语言入口。

### 交付物

- `agentService`
- `POST /api/v0/agent/query`
- 前端简版 Agent 页

### 具体任务

- 支持 3 种问题类型：
  - `author_daily_summary`
  - `author_stock_status`
  - `opinion_validation`
- 先查数据库
- 再查行情
- 最后组织自然语言结果

### 完成标准

- 用户能问：
  - “今天某人说了什么”
  - “某人提到的票现在怎么样”
  - “他说的板块回流现在成立吗”

### 验证方式

- 在页面输入问题
- 返回结构化可读答案

### 暂时简化

- 不做多轮上下文记忆
- 不做多人物对照
- 不做复杂工具规划

## 11. 任务包 8：联调与验收

### 目标

确保 V0 真正形成可运行闭环，而不是分散功能点。

### 交付物

- 联调清单
- 自测结果
- V0 演示流程

### 具体任务

- 从配置页录入帖子与作者
- 触发抓取
- 查看消息流
- 校验提及识别
- 校验行情绑定
- 校验推送
- 生成日报
- 通过 Agent 发问

### 完成标准

- 整条链路无阻塞
- 页面、接口、数据库三层结果一致

## 12. 推荐开发顺序

推荐严格按以下顺序推进：

1. 配置与建表
2. 抓取与解析
3. 去重与入库
4. 消息流页面
5. 提及识别
6. 行情绑定
7. 推送
8. 日报
9. 简版 Agent
10. 联调验收

这个顺序的原因是：

- 前 4 步先让数据链路活起来
- 中间 2 步让系统开始“理解”
- 后 2 步提升使用频率
- 最后 1 步给出统一入口

## 14. 风险最高的点

V0 阶段最可能出问题的是以下 4 点：

### 14.1 NGA 抓取稳定性

风险：

- 页面结构变化
- 登录态依赖
- 反爬限制

应对：

- 先固定一个帖子做验证
- 保留原始响应内容做调试

### 14.2 术语识别不准

风险：

- 黑话和简写多

应对：

- 先用少量高频规则
- 不在 V0 追求覆盖率，只追求高频可用

### 14.3 行情绑定过度复杂

风险：

- 一开始想把所有信号都做全

应对：

- V0 只做三类：个股、板块、黄线

### 14.4 范围失控

风险：

- 在 V0 阶段加入人物画像、多帖子、多渠道

应对：

- 所有新增需求都延后到 V1

## 15. V0 验收门槛

V0 只有满足以下门槛，才算真正完成：

- 能稳定监听一个帖子
- 能稳定过滤指定作者
- 能正确去重
- 能在页面展示消息流
- 能做基础提及识别
- 能做基础行情联动
- 能做一种即时推送
- 能做一种日报
- 能通过 Agent 进行基础查询

## 16. 下一步衔接

V0 完成后，不应立刻大规模加功能，而应先做三件事：

1. 复盘哪些对象识别最常用
2. 复盘哪类盘中提示最有价值
3. 再决定优先进入：
   - 人物画像
   - 持续观察任务
   - 多人物对照分析

## 17. 结论

这份开发任务拆解的核心目的，是让 V0 从“想法和文档”变成“可以立刻开始做的工程任务”。

只要严格按照这份顺序推进，就能在尽量短的周期内，产出一个可跑、可看、可推送、可查询的最小可用版本。
